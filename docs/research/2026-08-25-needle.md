# Needle 2 研究

**主题：** `cactus-compute/needle` 的定位、API 合约、部署边界与采用风险
**研究日期：** 2026-08-25
**资料截止：** 仓库 `main` 的 `7bd8a635ebb977489703b3bb916c21412e8a9cdf`（2026-08-23）
**资料范围：** 仅使用 Needle 官方 GitHub 仓库的 README、API 文档、包元数据和源码；未采用二手资料。模型大小、内存和基准表现均为项目方声明，未在本文独立复现。

## 结论摘要

Needle 2 是一个面向本地工具调用与结构化提取的 Python 包及配套推理引擎：应用声明工具 JSON Schema 或 Python 函数，模型产生函数调用 JSON，宿主程序再执行实际操作。项目将其定位为 45M 参数、单个 14MB 引擎、约 28MB 会话内存的超小型模型；这些性能和质量数字应作为待在目标设备与真实工具集上验收的供应商主张，而非安全保证。[官方 README](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/README.md)

最适合的场景是：网络可能受限、内存非常紧张、工具数有限或可容忍检索召回风险、并且上层已有授权与结果校验的设备端自动化或字段提取。它不是通用聊天模型：文档规定没有自由文本回退，不能匹配已声明工具的请求以空调用 `[]` 拒绝；真正执行工具、权限控制、幂等、审计和确认仍完全是宿主应用的责任。[官方 API 文档：行为与驱动循环](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#driving-the-loop)

## 一、产品与运行模型

README 把 Needle 2 描述为“tool calling、device use 和 structured extraction”模型。Python 包负责把工具描述交给本地 native engine，并提供 `Needle`、`tool`、`Field` 与 `extract` API；包自身要求 Python 3.9+，依赖 JAX/Flax/Optax、NumPy、SentencePiece 与 Hugging Face Hub，因而“推理内存很小”不等于安装包、训练环境或首次初始化的总体资源需求也相同。[包元数据](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/pyproject.toml) [公开 API 导出](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py)

引擎不是直接包含在 Python 源码里：初始化时，wrapper 依次查找 `NEEDLE_LIB_PATH`、已安装包目录和 `~/.cache/cactus-needle/<engine-version>/`；都不存在时才调用下载函数。README 说明预取并拷贝该引擎后，推理过程不再访问网络，并给出 `HF_HUB_OFFLINE=1` 用于缺件时快速失败的部署方式。[引擎定位源码](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L16-L28) [离线部署说明](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#offline-devices)

## 二、调用合约与可采用接口

`@needle.tool` 从函数签名和 docstring 构建 schema；也可以传 Pydantic model、原始 schema dict 或 JSON 字符串。`agent.complete()` 只走一个模型回合，调用者自行执行函数并把序列化结果传回；`agent.run()` 则在单一进程内执行已注册的 Python 函数，最多循环 `max_steps` 次（默认 8），最终把执行结果加到 `results`。因此，对于有副作用的操作，生产调用者应优先使用 `complete()`，在每一调用前增加身份、授权、参数、风险与幂等检查，而不应把 `run()` 直接绑定到高权限函数。[API 一览](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#api) [自动循环实现](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L85-L106)

输出是 JSON envelope，含 `type`、`function_calls`、`reasoning`、`confidence` 与速度/内存统计。文档称字节级 grammar 会根据已声明 schema 约束调用 JSON，并可将 `Field` 的范围、pattern、长度和枚举约束编入 grammar；这可降低不合 schema 的模型输出，但不验证业务语义，也不取代宿主端对金额、资源归属、权限和外部状态的校验。[响应格式与 schema 约束](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#declaring-tools) [行为契约](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#behaviour)

`needle.extract(text, schema)` 只是把 schema 作为唯一工具执行一次调用：有调用时返回 Pydantic 实例或 dict，没有调用时返回 `None`。这让输出形状可控，但业务上仍应把 `None`、缺失字段、低置信度或来源不可信的内容作为需要复核的状态，而非默认“抽取成功”。[提取文档](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#extraction) [提取实现](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L123-L140)

## 三、工具检索、上下文与置信度的边界

五个及以下工具会直接进入上下文；超过五个时，Needle 对工具和当前 query 做 embedding，只将得分最高的五个工具放进上下文，并将 grammar 重建为该子集。未选中的工具“不可达”，不是低概率候选。因此工具目录较大时，必须以真实请求集测量“正确工具被召回到 top-5”的比例，并为未召回情形设计重试、搜索或升级路径；仅评估最终 JSON 的合法性会掩盖这个失败模式。[工具检索机制](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#tool-retrieval)

README 宣称会话使用 256-token sliding window，且工具作为 KV sinks 固定以限制内存。该设计适合短任务和连续操作，但不应假定它能忠实保留长对话中的全部业务条件；涉及长期状态时，应由应用维护显式状态、再将必要事实作为当前输入或 `system` facts 传入。[README 的上下文与内存说明](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/README.md)

`confidence` 是校准 head 与调用 token 解码概率的最小值，项目建议业务方选择阈值，低于阈值时复问或路由到较大模型。关键限制是 LoRA 微调不更新该 head：源码在构造带 `weights` 的 agent 时告警，并在 `complete()` 中把 `confidence` 强制设为 `None`。采用微调权重时不能沿用基础模型阈值作为放行机制，必须建立独立的质量评测和保守的人工/规则兜底。[置信度定义](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#confidence) [微调权重的实现限制](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L52-L56) [强制置空逻辑](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L78-L82)

## 四、部署与并发限制

Python wrapper 以模块级全局变量保存 active engine 和已加载权重。载入 tuned `.cact` 后，不能再无歧义地构建 base-model agent；源码明确抛错而非静默用错权重，且 `extract()` 默认复用当前已加载的权重。这意味着同一解释器不适合混跑基础版与多个不同微调模型；应以进程隔离、一个 worker 一个权重版本，或在服务边界明确路由来处理。[共享引擎与权重绑定源码](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L45-L76) [提取的权重复用](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L123-L136)

`run()` 直接捕获工具函数抛出的异常，并把字符串错误作为下一回合模型输入；它不提供事务、超时、取消、重试策略、并发隔离或审计记录。生产集成应在工具实现或 orchestration 层提供这些能力，并把每次模型建议、授权判定、实际调用和外部结果写入独立审计链路。[`run()` 的错误和循环处理](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/__init__.py#L85-L106)

## 五、微调路径与评估建议

官方工作流为：可选地用 OpenRouter/OpenAI-compatible gateway 合成 JSONL 训练样本，使用 JAX 的 LoRA 微调冻结基座，随后将 adapter 合并并导出 `.cact`。生成数据需要 API key；基础 checkpoint 缺失时会自动下载。训练数据包含 query、tools、answers，且允许以 `answers: []` 表示无关请求。对安全或高价值工具，合成样本只能作为起点：还应保留人工审查的真实分布测试集，覆盖拒绝、歧义、越权、注入式工具结果、边界值和多步失败恢复。[README 的训练流程](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/README.md#fine-tuning) [数据生成提示与格式源码](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/needle/model/finetune.py#L30-L52)

建议的最小验收指标：

1. 对每个工具分别量测 schema-valid、正确工具选择、参数语义正确、应拒绝而拒绝、以及错误执行为零的比例。
2. 工具数超过五时，额外量测正确工具的 top-5 检索召回率。
3. 按目标硬件、冷/热启动、离线缓存命中和并发模型进程数测 p50/p95 延迟、峰值 RSS 与下载失败行为。
4. 对副作用工具，用 `complete()` 包裹策略引擎；低置信度、`None`、空调用与任何策略不确定性均不执行。

## 六、官方产品页补充（2026-08-25）

Cactus 的 Needle 2 产品页将设计目标限定为工具调用、设备操作和结构化抽取，并明确对比其与通用聊天模型的能力边界：消费设备的固定、类型化动作可被简化为“选择函数并填写参数”，不要求模型保有开放式世界知识或生成自由文本。该页面给出的发布配置是 45M 参数、14MB 单 binary、28MB 峰值 session RAM、CQ2-bit；使用 256-token sliding window，并将 system prompt 和工具定义固定为 KV sinks。因此“内存不随会话增长”是部署预算优势，同时也是长对话/长文档知识任务不应选 Needle 的原因。[Needle 2 官方产品页](https://cactuscompute.com/needle)

该页还强调：基础模型的训练内容集中在 smart home、mobile、wearables、TV、car 动作和结构化抽取，通用/企业 API 表面不在其主要分布；在固定工具词汇表上，项目建议通过本地 `needle finetune` 使用自有或合成 traces 微调。由此可得的采用结论是：微调可对齐某产品的有限工具 schema 与调用顺序，不能替代通用语言模型或 RAG 来获得 Kubernetes/Linux 的基础知识和长期文档上下文。[Needle 2 Evaluation 与 Fine-tuning](https://cactuscompute.com/needle)

## 七、现实使用场景：证据分级清单（2026-08-25）

本节只记录官方材料**明确展示或明确声称**的场景，不将“可定义任意函数”推演成已支持的行业方案。证据强度从高到低分为：**已确认生产部署**（厂商点名客户和产品）、**官方可运行 Sandbox 演示**（产品页列出的预设示例，浏览器内 WebAssembly 推理）和**仓库/API 示例**（说明接口能够表达的最小用法）。后三类不是客户案例，也不代表 Cactus 已对某一行业、设备或工作流作出可靠性承诺。

### A. 已确认生产部署

1. **Pebble Index 01 应用中的离线语音动作执行。** Cactus 产品页明确称 Pebble 在 Index 01 app 内本地运行 Needle，把 spoken requests 转成 actions；其创始人的引文说明这是面向无屏幕 Ring、在有网或无网时都要发生动作的交互。该条是目前在所查官方来源中唯一被点名的生产产品和客户案例。公开材料没有披露该应用具体暴露哪些工具、命令准确率、人工确认机制或可执行动作范围，因而不能把它扩展描述为“Pebble 的全功能语音助手”。[Needle 2：Production](https://cactuscompute.com/needle)

### B. 官方产品页的可运行 Sandbox 预设

产品页说明 Sandbox 在浏览器中以 WebAssembly 直接运行，并给出下列“Try an example”预设；它们是官方交互演示，而不是已部署的客户功能。页面还显示每个预设的调用形态（并行、链式、重复调用或拒绝），这是 Needle 的真实产品边界比单纯“能调工具”更具体的证据。[Needle 2 Sandbox](https://cactuscompute.com/needle)

|---|---:|---|

| Robot | 3-step sequence | 机器人动作的三步顺序调用 |

| Extract → email | structured call | 将结构化抽取结果传给邮件相关调用 |
| Currency | live API | 调用实时汇率 API |

这些预设共同覆盖了几个已演示的交互模式：单/多工具调用、并行、按顺序链式操作、对同一工具重复调用、数组参数、结构化抽取后交给另一工具、多个工具间路由，以及不匹配时的空调用。它们**不**证明模型拥有真实航班、汇率、邮箱、机器人或智能家居服务；演示中的实际数据源和执行器均由 Sandbox 所声明的工具决定。产品页的设计说明只主张模型负责将自然语言映射为“哪个函数、哪些类型化参数”，实际动作仍由宿主执行。[Needle 2：Function Call & Device Use](https://cactuscompute.com/needle)

### C. 官方仓库与 API 文档中的接口示例

1. **房间灯光控制。** API 文档定义 `set_lights(room, on, brightness)`，并展示将“living room”映射成房间、开关和亮度的结构化参数；README 的微调数据例子还使用“dim the kitchen to 10”。这是智能家居工具 schema、参数抽取和宿主执行循环的正式示例，不是某个已连接灯具品牌的集成声明。[API：声明与驱动循环](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#declaring-tools) [README：微调数据格式](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/README.md#fine-tuning)

2. **发票字段结构化抽取。** README 以一段发票文字抽出供应商、金额和到期日，返回类型化 `Invoice` 对象；该示例准确支持“离线文本到结构化记录”的场景，但没有说明 OCR、发票验真、税务合规或账务入库能力。[README：Extraction](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/README.md#extraction)

3. **引用/书目元数据抽取。** 微调文档给出 `extract_citation_data`，从期刊引用文本中抽取作者、标题和出版物字段。它是一个训练样本格式示例，足以说明自定义记录 schema 的用法，但不能声称项目提供文献管理产品或高精度引文解析器。[Fine-tuning 文档：数据格式](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/finetuning.md)

4. **带设备上下文的短指令消歧。** API 文档的 `system` facts 可提供日期、语言区域、设备、剩余电量、网络、位置、用户和助手等字段；官方具体说明日期事实可把“tomorrow at 7”转换为绝对时间，缺失日期时则保留原语。该例支持在手机/穿戴设备等客户端把受信任状态作为当前回合输入，而不是证明 Needle 会自行读取日历、GPS、电量或网络。[API：System facts](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#system-facts)

5. **气隙或断网设备上的本地函数调用/抽取。** 文档明确规定推理阶段不访问网络，且给出把引擎和 Python wheel 预下载、复制到设备、设置 `HF_HUB_OFFLINE=1` 的流程。该证据支持“离线部署一个由宿主提供工具的短任务组件”，不支持“无网仍可访问实时汇率、邮件、云端设备”这类需要外部工具本身具备连通性的结论。[API：Offline devices](https://github.com/cactus-compute/needle/blob/7bd8a635ebb977489703b3bb916c21412e8a9cdf/doc/apis.md#offline-devices)

### D. 与运维助手需求的严格对应

上述受证实场景中没有 Kubernetes、Linux shell、`kubectl`、SSH、日志分析或服务器运维的客户案例、Sandbox 预设或官方教程。官方产品页反而界定其训练分布为 smart home、mobile、wearables、TV、car 动作与结构化抽取，并明确指出企业 API 表面不在主要分布。因此，把 Needle 用于运维只能称作“基于自定义工具 schema 的待验证集成”，不能称为已有现实用例；若采用，至少需要自有 traces 微调、top-5 工具召回评测，以及由宿主实现的最小权限、审批和审计。[Needle 2：Evaluation](https://cactuscompute.com/needle) [Needle 2：Fine-tuning](https://cactuscompute.com/needle)
